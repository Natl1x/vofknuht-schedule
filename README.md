# Інтерактивний розклад ВоФК НУХТ

Flask-застосунок для перегляду та формування навчального розкладу. Дані
зберігаються у SQLite; адміністратор формує пари й створює облікові записи
викладачів, а викладачі залишають коментарі лише до закріплених за ними пар.

## Лабораторні роботи №1 і №2

Лабораторна №1, варіант 10, реалізована окремо від вебзастосунку в каталозі
[`lab01`](lab01/). Вона аналізує навчальний CSV з пасажирськими рейсами,
показує звіт у консолі та зберігає оброблені дані у JSON:

```bash
python lab01/main.py
python -m unittest discover -s lab01 -v
```

Звіти: [№1](lab-reports/lab01-report-yatskiv.md) і
[№2](lab-reports/lab02-report-yatskiv.md). Історію змін наведено в
[CHANGELOG.md](CHANGELOG.md). Лабораторна №2 спирається на Git-історію цього
репозиторію; стан командних вимог зазначено в її звіті. Навчальну вправу з
конфліктом злиття можна повторити командою `python lab02/conflict_demo.py`.

## Запуск

Потрібен Python 3.13+.

```bash
uv sync
uv run python main.py
```

На цьому комп’ютері відкрийте `http://127.0.0.1:5000`. Для доступу з іншого
пристрою тієї самої локальної мережі відкрийте `http://IP-АДРЕСА_КОМП’ЮТЕРА:5000`
(наприклад, `http://192.168.1.25:5000`). Якщо сторінка не відкривається,
дозвольте порт 5000 у брандмауері. Під час першого запуску автоматично
створюється `instance/schedule.db` та наповнюється демонстраційними даними.

## Демонстраційні акаунти

| Роль | Email | Пароль |
| --- | --- | --- |
| Адміністратор | `admin@vofknuht.local` | `admin123` |
| Викладач | `melnyk@vofknuht.local` | `teacher123` |

У реальному застосунку секретний ключ та початкові паролі слід змінити через
змінні середовища. Вони вказані тут лише для демонстрації лабораторної роботи.

## Можливості

- стартова сторінка з вибором групи та автоматичним завантаженням її розкладу;
- світла й темна тема, вибір якої зберігається у браузері;
- експорт розкладу групи до файлу `.ics` для Google Calendar, Apple Calendar та Outlook;
- форма відгуків;
- вхід за ролями `admin` і `teacher`;
- адмінпанель для викладачів, груп, предметів, аудиторій, відгуків і пар;
- одна дисципліна в довіднику, окремий вибір типу заняття та підгрупи для кожної пари;
- контроль конфліктів групи, викладача й аудиторії в один час;
- кабінет викладача з коментарями до власних занять.
- завантаження фото розкладу в адмінпанелі для подальшого розпізнавання.
- JSON API для розкладу, відгуків і коментарів із версіями v1 та v2.

Для розпізнавання українського тексту з фото на сервері потрібні Tesseract та
українська мовна модель `ukr.traineddata` у `instance/tessdata/`.

У формі заняття окремо обираються навчальна група, дисципліна, тип заняття
(лекція, практичне, лабораторна або «Не вказано») та підгрупа («Уся група»
або номер). Під час оновлення старі позначення на кшталт «Програмування (ЛР 2)»
переносяться в поля заняття, а дублікати дисциплін об'єднуються зі збереженням
пар і коментарів.

## Перевірка

```bash
uv run python -m unittest discover -s tests -v
```

Тести перевіряють публічні сторінки, створення й перегляд відгуків, обмеження ролей, коментарі
викладача й заборону конфліктів у розкладі.

## REST API — лабораторна робота №5

Документація доступна на [`/apidocs/`](http://127.0.0.1:5000/apidocs/), повна
схема запитів і відповідей — [`/openapi.json`](http://127.0.0.1:5000/openapi.json)
та у файлі `docs/openapi.json`. Усі маршрути починаються з `/api/v1` або
`/api/v2`. Версія v2 додатково повертає дату заняття поточного тижня, тип,
підгрупу, коментар і стан публікації. Запити із правами адміністратора або
викладача використовують cookie сеансу після `POST /api/v1/session`.

| Метод | Маршрут після `/api/{version}` | Призначення | Коди |
| --- | --- | --- | --- |
| POST / DELETE | `/session` | Вхід / вихід | 200, 204, 400, 401 |
| GET | `/groups`, `/subjects` | Довідники | 200 |
| GET | `/groups/{id}/lessons` | Опубліковані пари групи | 200, 404 |
| GET | `/lessons/{id}` | Дані пари | 200, 404 |
| POST / GET | `/feedback` | Надіслати / переглянути відгуки; email у списку бачить лише адмін | 200, 201, 400 |
| POST | `/lessons` | Створити пару (адмін) | 201, 400, 401, 403, 409 |
| PATCH / DELETE | `/lessons/{id}` | Змінити / видалити пару (адмін) | 200, 204, 400, 401, 403, 404, 409 |
| PUT / DELETE | `/lessons/{id}/comment` | Коментар до власної пари (викладач) | 200, 201, 204, 400, 401, 403, 404 |

Приклад публічного запиту:

```bash
curl http://127.0.0.1:5000/api/v2/groups/1/lessons
```

Для перевірки імпортуйте `docs/postman_collection.json` у Postman. Запускайте
запити **по порядку на свіжій демонстраційній базі**: колекція створює й
видаляє тестову пару та змінює її коментар. Змінна `baseUrl` за замовчуванням
дорівнює `http://127.0.0.1:5000`; `version` можна перемикати між `v1` і `v2`.
Сесійний cookie Postman зберігає автоматично. Кожен маршрут має успішний і
помилковий сценарій. Колекцію можна також запустити через Newman:

```bash
npx --yes newman run docs/postman_collection.json
```

Детальний звіт і результати перевірки наведено у
`lab-reports/lab05-report-yatskiv.md`.

## Клієнтська частина — лабораторна робота №6

Сторінка [`/feedback`](http://127.0.0.1:5000/feedback) використовує
`GET /api/v2/feedback` для списку й `POST /api/v2/feedback` для додавання
повідомлення. Шаблон розміщено у `templates/feedback.html`, асинхронну логіку
`fetch()` — у `static/js/feedback.js`. Сторінка показує завантаження, перевіряє
поля форми, відображає повідомлення сервера та оновлює список без
перезавантаження. Якщо JavaScript вимкнено, звичайна Flask-форма продовжує
працювати.

Публічний список API містить `id`, `name`, `message`, `created_at`; email
повертається лише адміністратору. Сторінка й API працюють на одному сервері,
тому CORS не потрібен. Скріншоти й результати браузерної перевірки — у
`lab-reports/lab06-report-yatskiv.md`.
