# Звіт до лабораторної роботи №6

**Тема:** Інтеграція клієнтської частини з API та обробка помилок.

| Відомості | Значення |
| --- | --- |
| Виконавець | Максим Яцків, ІПЗ 21 |
| Склад команди | Максим Яцків |
| Проєкт | Інтерактивний розклад ВоФК НУХТ |

Сторінка `/feedback` показує повідомлення з API й дозволяє надіслати нове
без перезавантаження. Після успішного `POST` список оновлюється окремим `GET`.
Під час запитів видно стан завантаження; помилки сервера та мережі
показуються зрозумілим текстом. Форма перевіряє обов’язкові поля й довжину
введення. HTML-шаблон — `templates/feedback.html`, JavaScript —
`static/js/feedback.js`, оформлення — `static/css/style.css`.

| API | Поля | Використання |
| --- | --- | --- |
| `GET /api/v2/feedback` | `id`, `name`, `message`, `created_at` | Завантажити список; для адміністратора додатково доступний `email` |
| `POST /api/v2/feedback` | `name`, `email`, `message` | Створити повідомлення; відповідь `201` або JSON-помилка |

Запити використовують відносну адресу на тому самому Flask-сервері. CORS не
потрібен. Email не відображається у публічному списку. JavaScript вставляє
текст через `textContent`, тому повідомлення не виконуються як HTML.

## Перевірка

Браузерна перевірка на тимчасовій SQLite-базі підтвердила завантаження
списку, приховування email, додавання без перезавантаження й показ
повідомлень про успіх та помилку. Помилку `400` змодельовано відповіддю API
у браузері; перевірка не створила запису. Помилок JavaScript у консолі не було.
Автоматичні тести перевіряють публічні й адміністративні поля відгуку та
попередній функціонал проєкту.

## Висновки

Клієнтська частина використовує API лабораторної №5 для читання й створення
відгуків. `async/await` дозволяє оновлювати список без перезавантаження
сторінки. Перевірка `response.ok` відрізняє успіх від HTTP-помилок, а стан
форми й повідомлення пояснюють користувачу результат дії.
