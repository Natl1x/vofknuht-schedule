# Звіт до лабораторної роботи №4

**Тема:** Реалізація бази даних для вебпроєкту «Інтерактивний розклад ВоФК НУХТ».

## 1. Відомості про проєкт

| Відомості | Значення |
| --- | --- |
| ПІБ | Максим Яцків |
| Група | ІПЗ 21 |
| Склад команди | Максим Яцків |
| Предметна область | Формування та перегляд навчального розкладу |
| Репозиторій | [Natl1x/vofknuht-schedule](https://github.com/Natl1x/vofknuht-schedule) |

У роботі функціональність умовного магазину з методичних рекомендацій
адаптовано до предметної області: замість товарів і замовлень реалізовано
формування навчальних занять, їх призначення викладачам і коментарі до пар.
Це забезпечує CRUD, зв’язки таблиць, адмінпанель і рольовий доступ.

## 2. Особистий внесок

Максим Яцків реалізував інтеграцію SQLite, структуру таблиць, ролі
адміністратора та викладача, адмінпанель, кабінет викладача, публічний розклад
і автоматичні тести. Код та документацію підготовлено за допомогою Codex.
Історія змін доступна у [репозиторії проєкту](https://github.com/Natl1x/vofknuht-schedule/commits/main).

## 3. Схема бази даних

```text
users (id, full_name, email, password_hash, role)
  ├── schedule_entries.teacher_id
  └── lesson_comments.teacher_id
groups (id, name, course) ─────── schedule_entries.group_id
subjects (id, name) ───────────── schedule_entries.subject_id
classrooms (id, name) ─────────── schedule_entries.classroom_id
schedule_entries (id, day_of_week, pair_number, starts_at, ends_at, is_published)
  └── lesson_comments.schedule_entry_id
feedback (id, name, email, message, created_at)
```

`schedule_entries` має зовнішні ключі на групу, дисципліну, викладача та
аудиторію. Унікальні обмеження не допускають дві пари одночасно для однієї
групи, викладача або аудиторії. `lesson_comments` має зв’язок з парою та її
викладачем; одна особа може мати один актуальний коментар до однієї пари.

## 4. Реалізована функціональність

- SQLite створюється автоматично у `instance/schedule.db`.
- Відвідувач може переглянути опублікований розклад, обрати групу та надіслати відгук.
- Адміністратор створює акаунти викладачів, керує групами, предметами й
  аудиторіями, додає, редагує, видаляє та публікує пари, а також видаляє відгуки.
- Викладач бачить лише власні заняття й може створити, змінити або видалити
  коментар до них. Коментар відображається студентам у публічному розкладі.
- Маршрути кабінетів закриті перевіркою ролі; паролі зберігаються як хеші.

## 5. Перевірка

Команда: `uv run python -m unittest discover -s tests -v`. Тести охоплюють
сторінки, створення відгуку, ролі, коментар викладача та конфлікт розкладу.

## 6. Труднощі та рішення

| Труднощі | Рішення |
| --- | --- |
| Статичний розклад не можна було редагувати | Дані перенесено до нормалізованих таблиць SQLite. |
| Можливі дублікати пар | Додано `UNIQUE` для групи, викладача й аудиторії. |
| Потрібно обмежити дії користувачів | Реалізовано сесію Flask, хешування паролів та перевірку ролі. |

## 7. Висновки

У проєкті реалізовано реляційну базу даних SQLite та формування розкладу.
Рольовий доступ дозволяє адміністратору керувати даними, а викладачам —
інформувати студентів про власні заняття.
