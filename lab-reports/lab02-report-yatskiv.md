## Середовище та репозиторій

Проєкт уже мав локальний Git-репозиторій, публічний GitHub-репозиторій `origin`, гілку `main`, [README](../README.md) з описом і запуском та [.gitignore](../.gitignore) для службових файлів. Історія комітів підтверджує виконання базових команд `add`, `commit` і `push` — наприклад, [початковий коміт](https://github.com/Natl1x/vofknuht-schedule/commit/7cf2d9f) і [коміт лабораторної №6](https://github.com/Natl1x/vofknuht-schedule/commit/730d7e4). Для цього завдання також налаштовано локальні Git-ім'я та адресу автора на основі попередніх комітів. Наявність GitHub-акаунта та віддаленого доступу підтверджена роботою з репозиторієм; налаштування SSH-ключа й 2FA звідси перевірити неможливо. Віддалений URL використовує HTTPS.

Для вправи з клонуванням і синхронізацією:

```bash
git clone https://github.com/Natl1x/vofknuht-schedule.git
cd vofknuht-schedule
git fetch origin
git status
```

## Внесок і Git workflow

Усі наявні модулі проєкту створено та супроводжено в одному репозиторії. Для лабораторної №1 додано CSV, модуль аналізу, консольний скрипт, перевірки й звіт; для №2 додано цей звіт і [CHANGELOG](../CHANGELOG.md). Робота відстежується у [GitHub Issue №1](https://github.com/Natl1x/vofknuht-schedule/issues/1), виконана в гілці [`feature/labs-01-02-variant-10`](https://github.com/Natl1x/vofknuht-schedule/tree/feature/labs-01-02-variant-10) та зафіксована [комітом `521c781`](https://github.com/Natl1x/vofknuht-schedule/commit/521c781). Створено [чернетку PR №2](https://github.com/Natl1x/vofknuht-schedule/pull/2), пов'язану з Issue №1. Рецензію іншого учасника не можна замінити самостійним злиттям, тому PR залишено відкритим.

Конфлікт злиття відтворено скриптом [conflict_demo.py](../lab02/conflict_demo.py) у тимчасовому репозиторії. Він створює гілки `feature/left` і `feature/right`, змінює однаковий рядок README, зливає першу гілку, отримує конфлікт під час злиття другої та зберігає обидві зміни у розв'язанні. Тимчасовий репозиторій видаляється після запуску; історія основного проєкту від вправи не змінюється.

```bash
python lab02/conflict_demo.py
```

```text
Git виявив конфлікт у README.md
Конфлікт розв'язано: Стан: варіант А і варіант Б
fix: resolve README merge conflict
```

## Що ще вимагає лабораторна

- Сформувати команду з 3–4 осіб, запросити її учасників до репозиторію та отримати реальний review.
- Перевірити особисті налаштування Git, SSH-доступ і 2FA в акаунті виконавця.
- За потреби додати скріншот навчального конфлікту до звіту.
- Для рівня 3 опублікувати реліз `v1.0.0` після перевірки та злиття PR.
- Підтвердити роботу з Git у VS Code та захистити лабораторну перед викладачем.

## Висновок

Існуючий проєкт забезпечує основу для лабораторної №2: публічний репозиторій, історію комітів, README і `.gitignore`. Командний workflow та особисті налаштування не можна чесно вважати завершеними без інших учасників і перевірки їхньої роботи.
